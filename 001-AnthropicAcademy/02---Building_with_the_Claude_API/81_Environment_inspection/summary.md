# [Environment inspection](https://anthropic.skilljar.com/claude-with-the-anthropic-api/287798)

## Summary

-  **Environment inspection** : Claudeが**自分の行動の結果**と**環境の現在の状態を観測できるよう**に、必要な情報・Tool・指示書を提供すること。Claudeは環境が見えないまま行動しているため、観測手段がなければ成否も次の状態も判断できない。
  - *事前検証(観測)* : ファイルを変更する前に**必ず現在の内容を読ませること**(= **Read before write**)で既存の構造を把握して初めて、既存機能を壊さずに変更できる
  - *事後検証* : Outputを検証するための方法を提供すること。
    - ex. スクリーンショットなどによる確認方法, UI操作toolの提供、API レスポンスの確認、生成物を要件と突き合わせる検証など
  - *benefit*
    - 修正の方針を都度調整可能 ⇒ エラーハンドリングなど都度修正しやすくなり、高品質なOutputが出しやすくなる

## Note/Tips

- 自身でAgentを作る際は以下のようにClaudeの立場に立って考えるとよい。
  - 「Claudeはどのようにして、この操作が**成功したと分かるのか**？」

- 観測手段はToolを与えるだけでは足りず、**system promptで「どう検証するか」まで指示する**と効く。
  - Claudeの作業で都度検証するたびにどう検証するか？は品質上の鍵になる。Promptに含めることで意図とのズレを軽減できる
  - 動画生成Agentの例では、生成した動画に対しwhisper.cppで字幕を書き出してセリフの位置を確認する／FFmpegで一定間隔のスクリーンショットを抜き出して映像を目視確認する、といった検証手順そのものをsystem promptに書いている。

## Supplement

- Claudeは我々が見えているもの(UI,ファイルの中身、フォルダ構成、API referenceなどのWeb上のドキュメント)が見えているわけではないので、適切な情報を伝える、あるいは適切な能力を与えることで同じ目線で修正ができるようになり、Outputが期待値にちかづく、ということだろう。
