# [A typical eval workflow](https://anthropic.skilljar.com/claude-with-the-anthropic-api/287736)

## Summary

- evalのWorkflow

    ```mermaid
    stateDiagram
    Evalのデータセットを作る --> Promptの草案を作る
    Promptの草案を作る --> Claudeを通してFeedする
    Claudeを通してFeedする --> Graderを通してFeedする
    Graderを通してFeedする --> Promptの草案を作る
    ```

  1. Evalのデータセットを作る
     - datasetには様々なタイプの質問や本番で想定される要求のinputのsampleが含まれる。
     - promptにPlaceholderがあればそれを埋め込まれた形の質問も含まれる。
     - データセット作成はEvalでは固定する必要があるため、最初に固定しループの外に配置する。

  2. Promptの草案を作る
  3. Claudeを通してFeedする
     - 1で作成したデータセットからpromptを一つ一つLLMへ送信し回答を得る
  4. Graderを通してFeedする
     - 入力したPromptとClaudeから得られたAnswerをセットでGraderに入力し、評価を得る。
     - データセットに対する評価結果はそれらの加算平均とする。
  5. Promptを変えて再度実行する
     - 4の評価結果がベースラインとし、promptを修正し、評価結果を得て改善したかどうかを確認する。

- Scoringのメリット
  - 定量的に客観的に何度も繰り返しPromptを評価でき、Bestなpromptを選択可能。
  - 単によさげな回答をくれそうな異なるPromptを使用するのではなく、定量的で確実に良くなったといえるpromptで実装できること

## Note/Tips

- dataset作成には自分で手動でやってもいいし、Claudeにつくらせてもいい。
  - システムの想定に関係のない質問も当然含まれる。

## Supplement

- Grader のスコアは 1〜10 のスケールが典型（10 = 完璧、低いほど改善余地あり）。スコアの絶対値そのものに意味はなく、同一データセット・同一 Grader 上で prompt 版どうしを比較するための指標として使う。

- 実運用のデータセットは数十〜数千件規模になりうる。件数が少ないと平均スコアが 1件の外れ値に振られる。

## Question

?Graderはどうやって作る？
> 回答: 一般的には **LLM-as-judge**、つまり Grader 自体をもう一つの Claude 呼び出しとして作るのが定石。採点基準（rubric）を system prompt で与え、質問と回答を渡して 1〜10 のスコアと採点理由を構造化出力（JSON / tool use）で返させる。ほかに、正解が一意に決まるタスクなら完全一致・正規表現・コード実行結果の検証といった**コードベースの Grader**、最終確認としての**人手評価**もある。実務では「コードで判定できるものはコード、できないものだけ LLM」と使い分ける。

?Datasetは流通しているものを使う？majorなものはある？
> 回答: 一般知識としては MMLU / GSM8K / HumanEval / BIG-bench などの公開ベンチマークが存在するが、これらは**モデルの汎用性能を比較する**ためのもので、prompt 評価には基本的に使わない。prompt 評価で測りたいのは「自分のアプリの入力分布に対してこの prompt が機能するか」なので、自分のユースケース固有のデータセットを自作するのが原則。

?Datasetが毎回変わるとすると、自身で試した結果における相対評価で判断するということだよね？
> 回答: 前提が逆で、**データセットは毎回変えない**。origin の Step 5 は「prompt を変えて同じ評価プロセスをもう一度回す」であり、データセットと Grader は固定される（7.66 → 8.7 の比較が成立するのはこのため）。データセットが毎回変わるとスコア差が prompt の改善によるものか問題の難易度差によるものか区別できなくなる。そのうえで「相対評価で判断する」という理解自体は正しい: 8.7 という絶対値に意味はなく、同一条件下でベースラインより上がったかどうかだけを見る。
